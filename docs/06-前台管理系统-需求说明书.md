## 1. 文档说明

### 1.1 编写目的

本文档描述 ESB / xRPC 配套前台管理系统（以下简称「控制台」）的业务目标、范围、角色、功能需求、非功能需求与验收标准。它是 `07-前台管理系统-概要设计.md`、`08-前台管理系统-详细设计.md` 以及前端/后端实现的依据。

### 1.2 与后台文档的关系

- `01`~`05` 描述**现有 ESB 后台**的现状与改造建议；
- 本系列 `06`~`08` 描述**新增前台控制台**；
- 控制台复用后台的 8 张元数据表，但不修改后台运行进程（方案 A）。

### 1.3 术语对照

| 控制台文案 | 后台实体 | 数据表 |
|---|---|---|
| 渠道系统 | `CustomerSysname` | `esb_customer_sysname` |
| 渠道接口 | `CustomerTransactionInfo` | `esb_customer_transaction_info` |
| 源数据入参 Tag | `CustomerRequestTag` | `esb_customer_request_tag` |
| 源数据出参 Tag | `CustomerResponseTag` | `esb_customer_response_tag` |

## 2. 背景与问题陈述

后台是配置化元数据驱动网关，但当前所有元数据只能直接操作数据库，且：

1. 没有管理界面，配置人员必须懂表结构和字段含义；
2. Tag 以扁平化的 `parentTag` 字符串表达树结构，人工维护极易出错；
3. 没有配置校验，错误配置只能在运行时暴露；
4. 没有版本、审批、回滚，误配置影响面大；
5. 没有权限与操作审计，无法回答「谁改了什么」；
6. 查询交易日志、定位报文问题只能翻日志文件。

控制台的目标是把「改数据库」变成「在界面上配置 + 校验 + 发布 + 追溯」。

## 3. 建设目标与成功标准

| 编号 | 目标 | 成功标准 |
|---|---|---|
| G-01 | 可视化配置四类 Tag | 配置人员无需了解 `parentTag` 拼接规则即可完成树形配置 |
| G-02 | 配置可校验 | 提交前完成结构、唯一性、类型、定长长度校验，错误定位到具体字段 |
| G-03 | 配置可追溯 | 每次变更有版本、有差异、有操作人、可回滚 |
| G-04 | 业务全链路可见 | 渠道、数据源、接口、映射、日志、错误码在一个控制台内闭环 |
| G-05 | 权限与审计 | 不同角色只能做授权范围内的操作，关键操作全部留痕 |
| G-06 | 零侵入后台 | 现有 ESB 进程不改动即可完成配置与发布（方案 A） |

## 4. 角色与用例

| 角色 | 主要职责 | 典型操作 |
|---|---|---|
| 系统管理员 | 用户、角色、权限、系统参数 | 建用户、分配角色、管理密钥 |
| 配置员 | 日常接口与 Tag 配置 | 新建交易、配置四类 Tag、保存草稿、提交校验 |
| 审批员 | 审核配置变更 | 查看差异、批准/驳回、发布 |
| 运维 | 监控与故障处理 | 查日志、看缓存、在线调试、执行刷新 |
| 只读用户 | 查看配置与日志 | 查询，无写权限 |

主用例 UC-01「新增一个交易接口」：

1. 配置员新建渠道接口（交易码、绑定渠道、处理 Bean、上下架）；
2. 新建/复用数据源接口（目标交易码、协议、地址、编码）；
3. 分别配置源数据入参/出参、目标数据入参/出参四类 Tag；
4. 粘贴样例报文，执行 Tag 校验与转换预览；
5. 保存为草稿，提交审批；
6. 审批员查看差异并批准；
7. 配置员发布，系统记录版本；
8. 按当前生效方式（方案 A：重启或后续刷新端点）使配置生效。

## 5. 范围与边界

### 5.1 范围内

- 渠道系统、渠道接口、数据源接口的增删改查与启停；
- 四类 Tag 的树形编辑、校验、预览、导入导出、复制；
- 字段映射可视化对照；
- 配置草稿、版本、差异、发布、回滚、审批；
- 交易日志查询与详情；
- 在线调试（四段式中间结果展示）；
- 错误码字典、报文样例库；
- 密钥、TCP 端口映射、日志开关管理；
- 用户/角色/权限与操作审计；
- 缓存状态与健康检查。

### 5.2 范围外

- 修改现有 ESB 运行时代码（本次不改后台）；
- 后台 P0/P1 缺陷修复（见 `04`）；
- 服务发现、灰度、熔断等平台能力（仅预留扩展点）；
- 渠道自助接入门户。

## 6. 功能需求

### F-01 工作台

| 项 | 内容 |
|---|---|
| 描述 | 展示交易总数、上架数、今日调用量、成功率、异常 Top、最近变更、待办 |
| 验收 | 数据与后台表一致；点击卡片可跳转到对应列表 |

### F-02 渠道系统管理

| 项 | 内容 |
|---|---|
| 描述 | 维护 `systype`、`sysname`、`flag`、`size`、`str1~str5` |
| 验收 | 支持新增/编辑/启停/搜索/分页；`sysname` 唯一；启停后立即影响渠道白名单配置的可选项 |

### F-03 渠道接口管理

| 项 | 内容 |
|---|---|
| 描述 | 维护 `tranno`、`sysname`（多系统逗号分隔）、`clazz`、`iscryption`、`isOpen`、`size` |
| 验收 | 交易码唯一；`clazz` 从白名单下拉选择（默认 `defaultService`）；上下架有确认提示；删除时检查是否有关联 Tag 与数据源接口 |

### F-04 数据源接口管理

| 项 | 内容 |
|---|---|
| 描述 | 维护 `providertranno`、`customertranno`、`datatype`、`sendurl`、`sysname`、`codeType` |
| 验收 | 一个渠道交易码可关联多个数据源接口；`datatype ∈ {json,xml,dc}`；`codeType ∈ {UTF-8,GBK}`；URL 格式校验 |

### F-05 Tag 配置中心（核心）

| 项 | 内容 |
|---|---|
| 描述 | 以树形结构编辑四类 Tag，字段包括 `tagName/parentTag/tagMapping/tagType/tagValue/sort/tagflag/taglength` |
| 验收 | 见下文 6.1 详细验收项 |

#### 6.1 Tag 编辑器详细验收项

1. 树形展示，节点层级由 `parentTag` 路径推导，根节点的 `parentTag` = 交易码；
2. 新增子节点自动生成 `parentTag`（父 `parentTag` + 「.」+ 父 `tagName`）；
3. 同父节点下 `tagName` 唯一，`sort` 唯一；
4. `tagType` 取值限定为 `String/Object/List/SizeList/NoSizeList`；
5. `tagflag` 取值限定为 `TOP/code/message/nonce/timestamp/channel/ListSizeCount`；
6. 协议为 DC 且 `tagType` 为标量时 `taglength` 必填且为正整数；
7. 提供环检测、孤儿节点检测、深度上限（默认 20 层）；
8. 删除父节点时提示级联删除子节点；
9. 支持从样例 JSON/XML 自动推断 Tag 骨架；
10. 支持把一个交易的某类 Tag 复制到另一个交易；
11. 支持批量导入/导出（Excel/JSON）；
12. 保存前执行校验并展示每条 Tag 在样例报文中的取值结果；
13. 拖拽调整 `sort` 后自动重新编号。

### F-06 字段映射视图

| 项 | 内容 |
|---|---|
| 描述 | 按 `tagMapping` 对齐渠道入参与目标入参字段，标出未映射与多余字段 |
| 验收 | 双向对照；显示映射类型与长度；支持一键跳转到对应 Tag 编辑 |

### F-07 配置发布与版本

| 项 | 内容 |
|---|---|
| 描述 | 草稿 → 校验 → 差异对比 → 审批 → 发布 → 版本留档 → 回滚 |
| 验收 | 版本含环境、对象类型、对象键、版本号、状态、快照、差异、操作人、审批人、发布时间；任一已发布版本可回滚且生成新版本 |

### F-08 交易日志查询

| 项 | 内容 |
|---|---|
| 描述 | 按 `tranflag(serid)`、`nonce`、`trancode`、`reqchannel`、时间范围、响应码查询 |
| 验收 | 列表分页；详情展示请求/响应报文（脱敏）、耗时、四段中间数据；支持导出 |

### F-09 在线调试

| 项 | 内容 |
|---|---|
| 描述 | 输入渠道报文，调用转换链并返回四段中间结果 |
| 验收 | 展示 `原始Map → customer_req_map → provider_req_map → 目标报文` 及逆向过程；错误时展示错误码与失败步骤 |

### F-10 报文样例库

| 项 | 内容 |
|---|---|
| 描述 | 按交易码维护请求/响应黄金样例 |
| 验收 | 样例可作为 Tag 骨架生成与校验输入；支持版本备注 |

### F-11 错误码字典

| 项 | 内容 |

| 验收 | 与 `05` 附录现状保持一致；支持搜索；新增码需唯一 |

### F-12 密钥管理

| 验收 | 支持轮换、启用/停用、到期提醒；私钥密文引用不可在列表接口返回 |

### F-13 TCP 端口映射与日志开关

|---|---|

| 验收 | 字段完整（`trannos/address/port/charset/fixedlength/type`）；8 类日志开关可独立切换；变更后展示生效提示 |

### F-14 缓存与健康管理

| 项 | 内容 |
|---|---|
| 描述 | 展示缓存模式、各 Hash 条目数；提供刷新触发入口（方案 B 预留） |
| 验收 | 方案 A 下刷新按钮为「需重启生效」提示态；接口按方案 B 契约预留 |

### F-15 用户、角色与权限

| 项 | 内容 |
|---|---|
| 描述 | RBAC，菜单与按钮级权限 |
| 验收 | 五种内置角色；无权限用户看不到菜单且接口返回 403 |

### F-16 操作审计

| 项 | 内容 |
|---|---|
| 描述 | 记录用户、时间、IP、对象、动作、变更前后值 |
| 验收 | 所有 POST/PUT/DELETE 自动留痕；不可删除审计记录 |

### F-17 接口模拟器（渠道发报模拟）

| 项 | 内容 |
|---|---|
| 描述 | 提供简化版 Postman 能力，模拟渠道系统向 ESB 发起请求；HTTP 走 admin 代理避免跨域，TCP 由 admin 代理建立 Socket 连接（浏览器无法直连 TCP） |
| 协议 | HTTP：`/controller/jsonHandler`、`xmlHandler`、`fixedLengthHandler`、`defaultHandler`；TCP：JSON 9999 / XML 9997 / DC 9998，帧格式 `[6位长度][报文]` |
| 功能 | 预置报文模板、渠道报文生成器（交易码/渠道/流水号/时间戳/业务数据）、自定义报文编辑、响应展示（状态/耗时/原始报文/JSON 格式化）、常用请求本地保存 |
| 兼容 | TCP 响应读取支持「自动兼容」，可处理当前接入端响应不带长度头的情况 |
| 验收 | 能分别通过 HTTP 与 TCP 发出 JSON/XML/定长报文并展示响应；Mock 模式下无后端也可演示 |

## 7. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| N-01 | 体验 | 常规查询响应 < 500ms；Tag 编辑 1000 节点内操作流畅 |
| N-02 | 兼容 | 前端支持 Chrome/Edge 现代版本；后端 Java 8 + Spring Boot 2.7.13 |
| N-03 | 安全 | 密码加盐哈希；JWT 有效期可配；接口防越权；敏感字段脱敏 |
| N-04 | 审计 | 操作日志保留不少于 180 天 |
| N-05 | 可维护 | 前端组件化，Tag 编辑器独立封装；后端分层清晰 |
| N-06 | 可验证 | 所有写接口有参数校验；错误响应结构统一 |
| N-07 | 部署 | 前端构建为静态资源，可由 Nginx 或 admin 服务托管 |
| N-08 | 扩展性 | 生效机制从方案 A 升级到方案 B 时，前端与接口契约不变 |

## 8. 数据需求

复用后台 8 张表；新增 11 张管理表，详见 `07` 第 5 节与 `08` 第 6 节。

## 9. 接口需求

统一前缀 `/admin-api`，统一响应结构；详见 `07` 第 6 节与 `08` 第 7 节。

## 10. 约束与假设

1. 后台无管理接口、无热更新，方案 A 下配置发布后需重启或等待既有加载时机生效；
2. 由于 P0-01（父 POM 模块路径错误）未修复，新 admin 模块以**独立工程**方式提供，不注册进现有 reactor，避免影响后台构建；
3. 环境无 Node/npm/Maven，源码交付后需在具备工具链的环境执行构建；
4. 控制台写入的业务表结构必须与实际库核对，`03` 中 DDL 为反推建议。

## 11. 验收标准

| 编号 | 验收项 | 标准 |
|---|---|---|
| AC-01 | 登录与权限 | 五种角色分别验证菜单与接口权限 |
| AC-02 | 配置闭环 | 完成 UC-01 全流程 |
| AC-03 | Tag 校验 | 6.1 的 13 项逐项通过 |
| AC-04 | 版本回滚 | 发布后回滚，数据恢复且生成新版本 |
| AC-05 | 日志查询 | 按 serid 精确定位一笔交易 |
| AC-06 | 审计 | 任一写操作可在审计页查到前后值 |
| AC-07 | 生效机制 | 方案 A 提示明确；刷新接口契约存在且被调用方预留 |

## 12. 风险与开放问题

1. 方案 A 的「发布后需重启」体验差，需尽快升级方案 B；
2. `clazz` 白名单来源未定：硬编码枚举还是读取 Spring 容器中的 Bean 列表；
3. 审批流是否需要多级、是否支持会签；
4. 多环境隔离是「一套控制台连多库」还是「一套库加 env 字段」；
5. 密钥管理的私钥托管方式（配置加密 / KMS）待定。
