## 2. Tag 树模型与转换算法（核心）

### 2.1 存储模型

后台 Tag 表是扁平结构，公共字段定义于 `com.xs.model.Tag`：

| 字段 | 列 | 类型 | 含义 |
|---|---|---|---|
| tagName | tagname | String | 标签名 |
| parentTag | parenttag | String | 父路径 |
| tagMapping | tagmapping | String | 源取值路径（点分） |
| tagType | tagtype | String | String/Object/List/SizeList/NoSizeList |
| tagValue | tagvalue | String | 固定值/默认值 |
| sort | sort | Integer | 同级顺序 |
| tagflag | tagflag | String | 语义标记 |
| taglength | taglength | Integer | 定长长度 |

每张 Tag 表还有 `id`、归属键（`customertranno` 或 `providertranno`）以及 `str1~str5`。

### 2.2 树构造规则（与后台 `MapConvert` 对齐）

```text
根集合：parentTag == 归属键 的 Tag
子节点集合：parentTag == 当前节点.parentTag + "." + 当前节点.tagName
同级排序：按 sort 升序
```

> 归属键：渠道请求/响应 Tag 用 `tranno`（如 `TRANNO001`）；数据源请求/响应 Tag 用 `providertranno`（如 `P001`）。后台 `DefaultAbstractService` 分别以这两个键调用 `MapConvert.mapperMap`，前台 Tag 配置页会自动切换归属键。

前端 `utils/tagTree.ts` 提供纯函数：

```ts
buildTagTree(tags: Tag[], ownerKey: string): TagNode[]        // 扁平 → 树
flattenTagTree(nodes: TagNode[], ownerKey: string): Tag[]     // 树 → 扁平，自动重算 parentTag
reindexSort(nodes: TagNode[]): TagNode[]                      // 拖拽后重排序号
detectCycle(tags: Tag[]): Tag[]                               // 环检测
detectOrphan(tags: Tag[], ownerKey: string): Tag[]            // 孤儿节点
inferFromSample(sample: string, type: 'JSON'|'XML'): Tag[]    // 样例 → 骨架
```

### 2.3 环检测算法

对每个节点，沿 `parentTag` 路径向上回溯：

1. 把 `parentTag` 按 `.` 拆成路径段；
2. 路径首段必须等于 `ownerKey`，否则记为孤儿；
3. 路径任一段与当前 `tagName` 相同且层级更深时判为环；
4. 深度 > 20 判为超限。

### 2.4 Tag 校验规则（`TagValidator`）

| 规则 | 级别 | 说明 |
|---|---|---|
| tagName 非空 | ERROR | 必填 |
| 同级 tagName 唯一 | ERROR | `(ownerKey, parentTag, tagName)` 唯一 |
| 同级 sort 唯一 | ERROR | 定长报文下 sort 决定顺序 |
| parentTag 合法 | ERROR | 必须等于 ownerKey 或可解析到已有节点 |
| tagType 枚举 | ERROR | String/Object/List/SizeList/NoSizeList |
| tagflag 枚举 | ERROR | TOP/code/message/nonce/timestamp/channel/ListSizeCount |
| DC 标量 taglength 必填 | ERROR | `datatype=dc` 且 tagType∈{String,List} |
| taglength 正整数 | ERROR | > 0 |
| Object/List 有子节点 | WARN | 否则映射结果为空 |
| tagMapping 可在样例中取值 | WARN | 用 `MapUtil.getVal` 等价逻辑解析 |
| 出参必须有 code/message 标记 | WARN | 否则 `DefaultService` 抛 `092` |
| 深度 ≤ 20 | ERROR | 防止递归栈溢出 |

校验结果结构：

```json
{
  "passed": false,
  "errors": [{"tagId": 12, "field": "tagName", "code": "TAG_NAME_EMPTY", "message": "标签名不能为空"}],
  "warnings": [],
  "preview": [{"tagId": 12, "path": "transaction.header.msg.seqNb", "value": "111106500000497"}]
}
```

### 2.5 样例推断算法

- JSON：解析后深度优先遍历，对象生成 `tagType=Object` 节点，数组生成 `SizeList` 子节点 + `ListSizeCount` 计数节点，标量生成 `String` 节点；`tagMapping` = 从根开始的点分路径。
- XML：先转 JSON（等价后台 `XML.toJSONObject`），再走 JSON 逻辑。
- 推断结果仅作为草稿，必须人工确认。

### 3.2 `TagTreeEditor` 组件契约

```ts
interface TagNode {
  id?: number
```

### 3.3 Axios 封装

```ts
// src/api/request.ts
const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE || '/admin-api',
  timeout: 15000
})
request.interceptors.request.use(cfg => {
  const token = useUserStore().token
  if (token) cfg.headers.Authorization = `Bearer ${token}`
  return cfg
})
request.interceptors.response.use(
  res => {
    const body = res.data
    if (body.code !== 0) {
      ElMessage.error(body.message || '请求失败')
      return Promise.reject(body)
    }
    return body.data
  },
  err => {
    if (err.response?.status === 401) router.push('/login')
    return Promise.reject(err)
  }
)
```

### 3.4 Mock 切换

`src/api/request.ts` 中根据 `VITE_USE_MOCK === 'true'` 决定走真实 Axios 还是 `src/mock/mockServer.ts`。Mock 使用 localStorage 持久化，保证刷新页面数据不丢，便于无后端演示。

### 4.4 版本状态机

```text
DRAFT --validate--> DRAFT(VALIDATED)
DRAFT(VALIDATED) --submit--> REVIEWING
REVIEWING --approve--> APPROVED
REVIEWING --reject--> DRAFT
APPROVED --publish--> PUBLISHED
PUBLISHED --rollback--> ROLLED_BACK (并生成新的 PUBLISHED 版本)
```

`publish` 事务步骤：

1. 读取 `content_json`，反序列化为目标对象列表；
2. 写入业务表（Tag 类采用先删后插）；
3. 更新版本状态为 `PUBLISHED`，写 `publish_time`；
4. 记录审计；
5. 返回 `effectMode`（A: `RESTART_REQUIRED`；B: `REFRESHED`）。

### 4.6 安全实现

- `JwtUtil`：`io.jsonwebtoken` 0.11.x，HS256，过期时间 `esb.admin.jwt.expire-hours`；
- `SecurityConfig`：`/admin-api/auth/login` 放行，其余 `authenticated()`；`hasAuthority()` 控制按钮；
- `UserDetailsServiceImpl`：查 `esb_admin_user` + 角色 + 权限码；
- `AuditAspect`：切 `@AuditAction(module, action)` 注解，记录 before/after JSON，password/key 字段替换为 `******`。

## 6. API 明细（核心接口）

### 6.1 `PUT /admin-api/tags/batch`

请求：

```json
{
  "ownerType": "CUSTOMER_REQUEST",
  "ownerKey": "TRANNO001",
  "tags": [
    {"id":1,"tagName":"transaction","parentTag":"TRANNO001","tagMapping":"transaction",
     "tagType":"Object","sort":1,"tagflag":"TOP"},
    {"id":2,"tagName":"seqNb","parentTag":"TRANNO001.transaction",
     "tagMapping":"transaction.header.msg.seqNb","tagType":"String","sort":1}
  ]
}
```

响应：`{code:0, message:"ok", data:{saved:2}}`。事务：先删除 ownerKey 下全部 Tag，再批量插入；任何校验失败整体回滚。

### 6.2 `POST /admin-api/tags/validate`

请求：`{ownerType, ownerKey, protocol, sample, tags}`。响应见 2.4 的 `TagValidateResult`。

### 6.3 `POST /admin-api/versions/{id}/diff`

响应：

```json
{
  "code":0,
  "data":{
    "added":[...],"removed":[...],"modified":[
      {"field":"taglength","before":6,"after":8}
    ]
  }
}
```

## 9. 已知取舍

1. 方案 A 下配置发布不会立即生效，必须明确提示，避免用户误以为失败；
2. `TagService.batchSave` 采用先删后插，发布瞬间存在极短空窗；后续可改为差异更新；
3. 在线调试若 `dryRun=false`，需要 ESB 提供可复用转换接口；当前先以 `dryRun=true` 本地复现为主；
4. 映射可视化在 P1 先用双栏对照实现，Vue Flow 连线作为增强；
5. 多环境先以 `esb_config_version.env` 字段区分，不做多库连接。
