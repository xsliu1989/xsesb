## 前端请求后端 403 修复

- 现象：前端（Vite 9520，`/admin-api` 代理到 9521）请求后台报 403。
- 定位：curl 验证无 token / 无效 token 请求 `/admin-api/auth/me` 返回 **403 且空响应体**；用配置密钥生成有效 JWT 后返回 200。JWT 配置为 `expire-hours: 12`，昨天登录的 token 已过期。根因是浏览器 localStorage 里残留过期 token（`mock-token-*` 或昨天签发的 token），Spring Security 对未认证请求默认回 403，前端拦截器只处理 401，所以用户只看到 403。
- 修复：
  - `xrpc-admin/src/main/java/com/xs/admin/config/SecurityConfig.java`：加 `exceptionHandling().authenticationEntryPoint()`，未认证返回 **401 + JSON** `{"code":401,"message":"登录已过期，请重新登录"}`，保留 slf4j 风格。
  - `xrpc-admin-web/src/api/request.ts`：响应拦截器把 403 也当登录失效处理，先 `useUserStore().logout()` 清掉 localStorage 里的旧 token，再跳 `/login`。
- 验证：后端 `mvn -pl xrpc-admin -am compile` 通过；前端 `npm run build` 通过。
- 生效条件：**需重启 IDEA 里的 xrpc-admin(9521)** 才能让 401 改动生效；Vite dev 会热更新前端改动。用户当前可先手动清 localStorage 的 `xrpc-admin-token` 并重新登录，立刻解除 403。

## 挡板未启动时返回明确提示

- 需求：后台挡板（8888，moco）未启动时，请求不通，需要 catch 并返回"第三方连接未启动或超时"。
- 调用链：accept-http(JsonController) → process(ConfigAction → DefaultAbstractServiceRedis.execute 第96行) → `OKHTTPUtil.postFormStr()`（xrpc-common-serve）。原逻辑把所有异常统一转成 `865 转换失败,请检查配置或上送格式`。
- 修复：`xrpc-common-serve/.../OKHTTPUtil.java` 的 `postFormStr()` catch 加 `isConnectFailure(e)` 根因判断（递归遍历 cause 链，匹配 ConnectException/SocketTimeoutException/UnknownHostException 或 message 含 Failed to connect/Connection refused/timeout），命中则抛 `DefineException("8004","第三方连接未启动或超时",e)`；8004 在错误码表里即"连接拒绝，请确认对方服务是否启动"。DefineException 会经 process → accept-http 一路透传到前端。
- 验证：`mvn -pl xrpc-module/xrpc-module-process -am compile` 通过；直连不存在端口实测抛 `code=8004 / 第三方连接未启动或超时`。
- 生效条件：**需重启 process(9301)** 加载新 class；挡板仍按 `后台挡板/启动.txt` 用 UTF-8 启动。
